# よくある質問とトラブルシューティング

よく寄せられる質問への簡潔な回答を、トピック別にまとめています。各回答では確認すべき点を説明し、詳しい手順が記載されたガイドにリンクしています。質問が見つからない場合は、**IT に質問**を使用するか、[問題を報告](employees.md#問題を報告する)してください。

## サインイン

### アカウントがロックされた

**失敗した試行が多すぎます。数分後にもう一度お試しください。** は、パスワードを何度か間違えたため、ISBP がアカウントを短時間ロックしたことを示します。しばらく待ってから、もう一度お試しください。ローカル アカウントのパスワードを忘れた場合は、サービス デスクに新しいパスワードの設定を依頼してください。会社のアカウント (**… でサインイン**) でサインインしている場合は、そちらでパスワードをリセットします。[サインインする](README.md#サインインする)を参照してください。

### サインイン時に新しいパスワードの設定を求められる

管理者がパスワードを設定し (新しいアカウントの場合、またはパスワードを再設定した場合)、それを変更するよう求めています。伝えられたパスワードを**現在のパスワード**に入力し、10 文字以上の**新しいパスワード**を 2 回入力して、**パスワードを変更**を選択します。変更するまでは、ISBP を開くたびに**新しいパスワードを設定してください**の画面に戻ります。[サインインする](README.md#サインインする)を参照してください。

### アカウントが設定されていないと表示される

**お使いのアカウントは、このプラットフォームでまだ設定されていません。** は、会社のアカウントは有効ですが、ISBP にユーザーとして登録されていないことを示します。サービス デスクまたは ID 管理者に追加を依頼してください。**このアカウントは有効ではありません。管理者にお問い合わせください。** は、アカウントが事前登録、一時停止、オフボーディングのいずれかの状態であることを示します。

### サインアウトされた

**セッションの有効期限が切れました。もう一度サインインしてください。** は、セッションが終了したとき、またはセッションがサインアウトされたとき (パスワードの変更後や、別のデバイスで**他のセッションをサインアウト**を使用したときなど) に表示されます。もう一度サインインしてください。自分のデバイスでサインインしたままにするには、**このデバイスでサインインしたままにする**をオンにします。

## アクセスとアクセス許可

### ページやボタンが表示されない

ISBP には、ロールで許可されているものだけが表示されます。使用できないページはサイドバーに表示されず、直接開くと**このページへのアクセス権がありません。** と表示されます。

1. **プロファイルと設定 → 自分のアクセス権**を開き、自分のロールを確認します。
2. さらにアクセスが必要な場合は、ロールが申請可能であれば[アクセスを申請](employees.md#アプリケーションやロールへのアクセスを申請する)するか、上長または管理者に依頼してください。

必要なロールの例: **サービス デスク**のページには**サービス デスク担当者** (Service desk agent) ロール、**統合**には**統合管理者** (Integrations administrator) または**統合閲覧者** (Integrations viewer)、**アシスタント**ボタンには**アシスタント ユーザー** (Assistant user) が必要です。**このページは存在しないか、モジュールが無効になっています。** と表示される場合は、管理者が**管理 → モジュール**でその領域をオフにしています。

### まだ入社していない新しい同僚のアクセスを申請できますか?

はい。人事がその同僚を**事前登録**として追加すると、**アクセスの申請**で**他の人**を選択して、その同僚を選べるようになります (**事前登録**と表示されます)。申請が承認されるとアクセスが付与され、初日に人事が**オンボーディング**を選択した時点から使えるようになります。[新入社員が月曜日に入社する](how-it-fits-our-work.md#シナリオ-新入社員が月曜日に入社する)を参照してください。

事前登録されたユーザーは、その上司と、その部署のアクセスを管理するユーザーにのみ表示されます。表示されない場合は、人事が自分をその人の**上司**として設定しているかを確認してください。**このユーザーは一時停止中です。先に再有効化してください。** と**このユーザーはオフボーディング済みです。** は、その人のアカウントが一時停止されているか閉鎖されていることを示します。この場合、その人について新しいアクセスは申請できません。

## 申請と承認

### 申請が進まない。誰の対応を待っているのか?

**申請 → 自分の申請**から申請を開きます。**承認ルート**に各ステップが表示され、現在のステップには**対応待ち**と承認者の名前が表示されます。**自分の申請**の行にも、承認者の写真とともに **… の待ち**と表示されます。

- 承認ステップには期限があります。承認者にはリマインダーが届き、ワークフローによっては、期限を過ぎると申請がエスカレーションされます (上長の上長など)。
- 承認者が不在の場合は、その人の不在設定の代理人に新しい承認が届きます。承認者に直接連絡するか、サービス デスクに相談することもできます。
- 管理者は、**管理 → ワークフロー → 実行中と履歴**で、実行中のすべての承認と、それぞれが待機しているステップ (**現在のステップ**) を確認できます。

### 承認ルートに「スキップ — 承認者がいません」と表示される

ワークフローがそのステップの承認者を見つけられず (プロファイルに上司が設定されていない場合など)、そのステップをスキップするように設定されていました。確認ステップ、またはフォームの**この申請の承認者**に**このステップを承認できる人がいないため、申請は却下されます**と表示される場合は、申請を送信しないでください。まず、上司、ロールの所有者、またはフォームの場合は選択したシステムのサポート グループの設定を修正するようサービス デスクに依頼してください。

### 「承認ワークフローがまだ設定されていません。」と表示される

申請に必要な承認ワークフローが公開されていません。**管理 → ワークフロー**でワークフローを公開するよう管理者に依頼してください。[管理者](administrators.md)を参照してください。

### 「このアクセス権にはすでに処理中の申請があります。」と表示される

自分 (または自分の代わりに誰か) がすでにそのロールを申請しており、まだ処理中です。**自分の申請**からその申請を開いてください。別の内容で申請する場合は、先にその申請を取り下げます。

### アクセスが承認されたのに、まだ付与されていない

付与は、最後の承認の少し後に行われます。申請を再読み込みすると、**アクセスが付与されました**と表示されるはずです。**付与できませんでした**と表示される場合は、ロールが削除されたか、対象者が有効ではなくなっています。サービス デスクに相談してください。

### 判断しようとした承認に「この承認はすでに処理されています。」と表示される

そのステップの他の承認者が先に判断したか (多くのステップでは最初の回答で決定します)、申請が取り下げられました。この承認が**承認 → 自分が判断済み**に表示されるのは、自分が判断した場合だけです。

### 休暇中も承認を滞らせないには?

**プロファイルと設定 → 不在設定**で不在設定をスケジュールします。新しい承認は、選択した同僚に送られます。[不在設定をする](employees.md#休暇の前に不在設定をする)を参照してください。

### フォームがポータルに表示されない

フォームが**申請 → 何が必要ですか？** に表示されるのは、次の条件をすべて満たす場合だけです。**管理 → フォーム**で確認するよう、ワークフロー管理者に依頼してください。

- 公開されている (状態が**下書き**ではなく**公開済み v…** と表示される)。
- **申請を受け付ける**がオンになっている (オフの場合は**一時停止中**と表示される)。
- **対象ユーザー**が**全員**、または自分を含む**特定のグループ**になっている。
- 承認ワークフローが公開されている。

[管理者](administrators.md)を参照してください。

### フォームのレコードの選択に、必要な構成アイテム (またはアプリケーション、資産) が表示されない

レコードの選択には、表示権限があり、かつフォームで受け付けられるレコードだけが一覧表示されます。たとえば、フォームによっては本番のシステムしか選択できません。**番号またはタイトルで検索…** に番号または名前の一部を入力してください。それでも表示されない場合は、その種類のレコードを表示するロール (構成アイテムの場合は **CMDB 閲覧者**) がない可能性があります。サービス デスク、またはフォームを管理しているユーザーに問い合わせてください。[ユーザーがレコードを選択できるようにする](processes.md#ユーザーがレコードを選択できるようにする)を参照してください。

### 申請は承認されたが、「その後の処理」に失敗と表示される

承認後にフォームが変更の作成などの処理を試みましたが、うまくいきませんでした。フォームを管理するユーザーにはエラーが通知されており、原因を修正した後に**再試行**で再実行できます。(**再試行中 (… 回目)** は、まだ自動的に再試行していることを示します。) 申請を再送信する必要はありません。[アクションの結果を確認する](processes.md#アクションの結果を確認する)を参照してください。

### フォームのリンクはどこにありますか?

公開済みのフォームには、それぞれ独自のアドレスがあります。ISBP のアドレスの `/requests/forms/<key>` です。管理者は、フォーム ビルダーの**その他の操作 → 申請ポータルで開く**でこれを開き、ブラウザーからアドレスをコピーします。フォームの**対象ユーザー**以外には「このフォームは利用できません」と表示されます。[フォームを公開してリンクを共有する](processes.md#フォームを公開してリンクを共有する)を参照してください。

## 通知と言語

### 通知が届かない

1. **プロファイルと設定 → 通知**を確認します。その種類の通知が、**アプリ内**または**メール**でオンになっている必要があります。
2. このプラットフォームではメール通知がまだ設定されていないことがページに表示される場合、通知はアプリ内でのみ届きます。管理者は、**管理 → 通知 → メール**でメールをオンにします。
3. Microsoft Teams や Slack への通知は、管理者が**管理 → 通知 → チャネル**で構成するチーム チャネルに送られ、個人には送られません。
4. 管理者は、**管理 → 通知 → 配信ログ**で、送信された通知と失敗した通知を確認できます。

[受け取る通知を選択する](employees.md#受け取る通知を選択する)を参照してください。

### 通知やメールは何語で届きますか?

自分の言語で届きます。各通知は送信時に受信者の言語で作成されるため、**言語**を変更すると、それ以降の新しい通知に反映されます。過去の通知は変わりません。Teams や Slack のチャネルに投稿されるメッセージには、そのチャネルの**メッセージの言語**が使用されます。

### 日付と時刻が正しくない

**プロファイルと設定 → 基本設定**で**タイム ゾーン**を設定するか、**このデバイスのタイム ゾーンを使用**を選択します。

## チケットとサービス デスク

### チケットが解決済みになったが、まだ直っていない

チケットを開き、**いいえ、まだ解決していません**を選択し、**まだ何が問題ですか?** に内容を入力して、**チケットを再オープン**を選択します。サービス デスクに通知されます。[解決を確認する](employees.md#解決を確認してサービスを評価する)を参照してください。

### IT に質問で作成したチケットはどこにありますか?

自分で報告した他のチケットと同様に、**申請 → 自分の申請**にあります。IT に質問の会話にも、そのチケットへのリンク (**チケットを表示**) が表示されます。

## IT に質問、アシスタント、変更セット

### IT に質問で「組み込み · LLM なし」と表示される

AI 言語モデルが構成されていません。それでも IT に質問は機能します。ナレッジ ベースの検索、類似チケット、テンプレートから回答し、チケットの準備もできます。**言語モデル**と表示される場合は、AI モデルが回答を作成しています。モデルは管理者が**管理 → AI** で選択します。[アシスタントと AI](assistant-and-ai.md)を参照してください。

### アシスタントにガイド付きテンプレートしか表示されない

AI チャット モデルが構成されていない場合、アシスタントは自由入力の代わりに**ガイド付きテンプレート** (**承認チェーン**、**申請フォーム**、**カスタム フィールド**、**SLA 目標**、**HTTP 正常性チェック**など) を表示します。**変更できる項目にガイド付きテンプレートがありません**と表示される場合は、アシスタントが変更できる構成へのアクセス権がありません。

### 「今月の AI 予算を使い切りました。」と表示される

管理者が設定した月間の AI 予算 (**管理 → AI → プライバシーと予算**) を使い切ったため、翌月になるか管理者が予算を引き上げるまで、AI モデルは呼び出されません。チケットの作成は引き続きできます。

### 変更セットに「変更セットの作成後に、この構成が他のユーザーによって変更されました。」と表示される

これは `CHANGE_SET_STALE` エラーです。変更セットの作成後に、誰かが同じワークフロー、フォーム、設定を編集したため、変更セットを適用するとその作業が上書きされてしまいます。

1. **管理 → 変更セット**で変更セットを開きます。
2. **更新**を選択します。変更セットが現在のバージョンに基づくものになります。
3. 差分と**ドライ ラン**を確認してから、もう一度適用するか、レビューを依頼します。

### 「この変更セットを自分で適用することはできません」と表示される

適用するには、自分が持っていないアクセス許可が必要です。**レビューを依頼**を選択してください。そのアクセス許可を持つ承認者が**承認**でレビューし、承認すると変更セットが適用されます。

### 変更セットをロールバックできない

ロールバックはすべての変更を一度に元に戻すため、いずれかのオブジェクトがその後変更されている場合や、変更セットで何かを削除した場合 (削除は自動的には元に戻せません) は拒否されます。代わりに、新しい変更セットで修正してください。[アシスタントと AI](assistant-and-ai.md)を参照してください。

## データ、ジョブ、データベース アクセス

### スケジュール ジョブが失敗した

1. **スケジュール ジョブ → 実行履歴**を開き、**失敗**で絞り込んで実行を開きます。**失敗の理由**にエラーが表示されます。
2. 原因 (接続できないデータベース接続など) を修正してから、**再実行**を選択します。
3. ジョブが連続して何度も失敗した場合は、ジョブが無効になっています (**… は無効になりました**)。ジョブを開いて**有効にする**を選択します。

ジョブのアラートがオンになっている場合、ジョブの所有者には**自分のジョブの実行が失敗したとき**の通知が届きます。[データと自動化](data-and-automation.md)を参照してください。

### 「ここではスクリプトを実行できません。サンドボックスが構成されていないか、イメージが許可されていません。」

スクリプト ジョブは、管理者が構成する必要がある分離されたコンテナーで実行されます。プラットフォーム管理者に相談してください。[データと自動化](data-and-automation.md)を参照してください。

### データベースのパスワードが表示されなくなった

**このパスワードは表示済みか期限切れです。** パスワードは、アカウントの作成から 7 日間、1 回だけ表示されます。DBA にリセットを依頼してください。

### 本番環境へのデプロイが拒否された: 「本番環境へのデプロイには承認済みの変更が必要です。」

本番環境へのデプロイには、CAB が承認した変更 (**スケジュール済み**または**実施中**) が必要です。その変更は、デプロイで指定されているか、リリースにリンクされている必要があり、場合によっては予定期間内である必要もあります。承認済みの変更をリンクするか、変更マネージャーであれば**変更を起票**で変更を起票してください。[変更とリリース](changes-and-releases.md)を参照してください。

## 統合

### 同期の競合が発生した

前回の同期以降に、同じフィールドが ISBP と ServiceDesk Plus または Azure DevOps Server の両方で変更され、プロファイルで人が判断するよう設定されています。

1. **管理 → 統合 → 同期の競合**に移動します。
2. 競合の**解決**を選択します。
3. フィールドごとに **ISBP の値を保持**または **… の値を保持**を選択するか、**両方をそのまま保持**を選択して、**適用**を選択します。

同期の競合を解決するアクセス許可 (**統合管理者**ロール) が必要です。[統合](integrations.md)を参照してください。

### 「接続先のシステムが接続の資格情報を拒否しました。」

接続に保存されている API キーまたは個人用アクセス トークンが間違っているか、期限切れです。統合管理者が接続の設定で更新します。

### 「この接続は暗号化されていない HTTP を使用しています。」

接続では既定で HTTPS を使用します。システムの HTTPS アドレスを使用してください。それが不可能な場合に限り、管理者は接続の**安全でない HTTP を許可する**をオンにできます (このスイッチの操作は監査されます)。
