# 管理員指南

本指南適用於 IT 與平台管理員。內容涵蓋誰可以做什麼（人員、群組、部門、角色與權限申請）、人員如何登入、每項申請背後的簽核流程與表單、通知、模組、AI 設定與稽核日誌。其中許多變更也可以由助理準備成變更集；最後的[常見的管理工作](#常見的管理工作)會列出兩種做法。

## 認識系統管理區

側邊欄的**系統管理**區只會顯示您有權限的頁面。下列系統角色是分派管理工作的常見方式；**平台管理員**（Platform administrator）可以執行所有操作。

| 頁面（系統管理 → …）                           | 用途                                    | 負責管理的角色                                                |
| ---------------------------------------------- | --------------------------------------- | ------------------------------------------------------------- |
| **人員**、**群組**、**部門**                   | 帳號、成員資格與組織樹狀結構            | **身分識別管理員**（Identity administrator）                  |
| **角色與存取權**                               | 角色、權限與擁有者                      | **平台管理員**（建立角色）；**身分識別管理員**（授予）        |
| **應用程式**、**API 用戶端**                   | 業務應用程式、其角色，以及服務帳戶      | **應用程式存取管理員**（Application manager）；**平台管理員** |
| **工作流程**、**表單**、**自訂欄位**、**通知** | 簽核、申請表單、額外欄位與通知傳送      | **工作流程管理員**（Workflow administrator）                  |
| **AI**                                         | 模型、隱私、預算、索引與外部代理程式    | **平台管理員**                                                |
| **稽核日誌**                                   | 每項變更與登入                          | **安全性稽核員**（Security auditor，全平台唯讀）              |
| **模組**                                       | 開啟或關閉模組，並變更其設定            | **模組管理員**（Module administrator）                        |
| **資料庫連線**                                 | 外部資料庫                              | **資料庫連線管理員**（Database connection administrator）     |
| **登入提供者**                                 | SSO 與目錄同步                          | **平台管理員**                                                |
| **整合**、**同步衝突**                         | ServiceDesk Plus 與 Azure DevOps Server | **整合管理員**（Integrations administrator）                  |
| **變更集**                                     | 透過助理準備的設定變更                  | **助理管理員**（Assistant administrator）                     |

模組也會加入自己的管理頁面，例如**服務台**（工單類別、SLA 政策、行事曆與服務目錄）。這些頁面在各領域的指南中說明。

## 新增人員並辦理到職啟用

以 SSO 登入的人員會在首次登入時自動建立（若提供者允許）。若要建立本機帳號，或在新進人員報到前預先建立帳號，請手動新增人員。

1. 前往**系統管理 → 人員**，選擇**新增人員**。
2. 填寫**身分**（公司電子郵件、使用者名稱、顯示名稱）、**組織**（部門、主管、職稱）與**帳號**（語言、時區）。
3. 在**初始狀態**下，選擇**立即啟用**（可立即登入）或**預先建立**（帳號已存在，但在完成到職啟用前無法登入）。
4. 若是本機帳號，請設定**初始密碼**（對方首次登入後，ISBP 會立即要求設定新密碼）。僅使用 SSO 的帳號請留空。
5. 加入**群組**：成為群組成員，即可取得指派給這些群組的角色。選擇**建立**。

**後續流程：** 到職日當天，開啟該人員並選擇**到職啟用**。人員的**存取權**分頁會顯示其有效權限，以及取得每項權限的原因：直接指派、透過群組，或透過「所有人」。

## 停權、重新啟用人員或辦理離職停用

在調查期間或長期休假時將人員停權；人員離職時，則為其辦理離職停用。

1. 在**系統管理 → 人員**中開啟該人員，選擇**更多動作**。
2. 選擇**停權**並填寫**原因**。對方會立即被登出，其存取權則會保留供日後使用。若要取消停權，請選擇**重新啟用**。
3. 若要辦理離職停用，請選擇**離職停用**。選擇是否要**移除所有群組成員資格**、**移除所有直接指派的角色**，以及**將直屬部屬移交給**某人，然後選擇**離職停用**。

**後續流程：** 離職停用會停用登入並結束所有工作階段。系統會通知各模組，讓它們移除自己管理的存取權（例如資料庫帳戶），並提醒資產管理員收回該人員的設備。所有動作都會記錄在稽核日誌中。**更多動作**中還有**從所有裝置登出**與**設定密碼**。若勾選**下次登入時要求變更密碼**，對方登入後會立即被帶到**個人資料與偏好設定**中的**請設定新密碼**，在變更密碼之前，即使重新載入頁面也無法略過。

## 以群組管理人員

請將角色授予群組，而不是逐一授予人員：加入群組的人都會取得該角色，離開群組的人則會失去該角色。

1. 前往**系統管理 → 群組**，選擇**新增群組**。輸入**名稱**與**索引鍵**（供整合與目錄同步使用，之後無法變更），然後選擇**建立**。
2. 開啟群組。在**成員**中選擇**新增成員**，找到人員後確認。
3. 在**角色**中選擇**授予角色**，即可將角色授予每位成員。

由目錄同步填入成員的群組會註明這一點；在這類群組中手動所做的變更，可能會在下次同步時被覆寫。**所有人**群組包含每位啟用中的人員，並提供基本存取權。

## 建立部門樹狀結構

部門用來將人員分組，也可以限制管理員能管理的範圍。在示範資料中，人資夥伴（`hr.partner`）只能管理 Sales 部門及其子部門中的人員。

1. 前往**系統管理 → 部門**，選擇**新增部門**；或開啟某個部門，選擇**新增子部門**。
2. 輸入**名稱**、簡短的**代碼**、**上層部門**與**主管**（工作流程可以請其簽核的部門主管）。選擇**建立**。

移動部門時，其下的所有內容都會一起移動。部門仍有子部門時無法刪除；刪除部門時，會撤銷以該部門為範圍的角色。

## 建立角色

角色是一組權限的集合。權限的命名格式為 `module.resource.action`（例如 `core.users.read`），`*` 則涵蓋整個模組或資源。

1. 前往**系統管理 → 角色與存取權**，選擇**新增角色**。
2. 輸入**名稱**、**索引鍵**與**描述**。
3. 在**權限**下勾選個別權限，或選取整個模組或資源，以萬用字元授予（日後新增的權限也會涵蓋在內）。選擇**建立角色**。

系統角色來自各模組，無法編輯：開啟系統角色並選擇**建立複本**，即可建立可編輯的複本。系統角色的名稱與描述會以每位人員的語言顯示；您建立的角色則會保留您取的名稱。您只能將自己擁有的權限放入角色中，ISBP 會拒絕其餘權限。在示範資料中，**HR partner**、**Directory lookup**（可讀取人員與群組）與 **Group manager** 是自訂角色。

## 授予具範圍與結束日期的角色

您可以將角色授予人員或群組，範圍可以是全域、單一部門或單一紀錄，也可以設定只到某個日期為止。臨時需求請優先使用有期限的存取權。

1. 前往**系統管理 → 角色與存取權**，選擇**授予角色**（或在人員頁面上選擇**管理存取權**）。
2. 選擇**角色**，然後在**授予對象**下選擇**人員**或**群組**。
3. 在**存取期限**下，選擇**永久**、**7 天**、**30 天**、**90 天**或**自訂日期…**（指定日期）。
4. 若要縮小範圍，請開啟**限定於部門或紀錄**並選擇**範圍**：部門（包含其子部門），或單一紀錄（例如某個群組）。
5. 輸入**原因**，然後選擇**授予存取權**。

**後續流程：** 授予會立即生效。有期限的授予會自動結束；被授予者若是人員（而非群組），會先收到「即將到期的權限」提醒。**指派**分頁會列出每一筆授予及其範圍、結束日期與授予者；選擇**撤銷**即可結束授予。

在示範資料中，`helpdesk` 只能管理 VPN Users 群組的成員（紀錄範圍）；一位約聘人員則為了模組上線，取得為期三天的**模組管理員**角色。

## 讓人員申請角色

與其由您逐一授予每個角色，不如讓人員在申請入口網站中提出申請。申請會經過簽核流程，核准後，系統會依核准的期限自動授予角色。

1. 在**系統管理 → 角色與存取權**中開啟角色。
2. 在**自助申請**中，開啟**人員可以申請此角色**。
3. 選擇**風險等級**（工作流程可將風險較高的申請交給更多簽核者）、**角色負責人**（當工作流程包含角色負責人簽核步驟時，由此人簽核）、**最長授予期限**，並視需要指定**簽核流程**。選擇**儲存變更**。

**後續流程：** 該角色會出現在入口網站的**申請權限**中（請參閱[員工](employees.md)）。除非您選擇了其他流程，否則申請會使用預設的**權限申請**流程。在示範資料中，**模組管理員**最長可申請 30 天，並經過 **Privileged access** 流程簽核。

## 管理業務應用程式及其角色

註冊業務應用程式（例如示範資料中的 Finance ERP），讓它的存取權也能像平台存取權一樣授予、申請、核准、到期與稽核。應用程式會透過角色查詢 API 詢問誰可以做什麼。

1. 前往**系統管理 → 應用程式**，選擇**註冊應用程式**。輸入**名稱**、**識別碼**（應用程式呼叫 API 時使用，之後無法變更）與**負責人**，然後選擇**註冊**。
2. 在**權限**中，加入應用程式會檢查的動作，例如 `invoices.approve`。
3. 在**角色**中選擇**新增角色**，挑選其權限，並在**自助申請**下決定是否開放人員申請。
4. 在**擁有存取權的人員**中選擇**授予存取權**，將角色授予人員或群組。
5. 在**角色查詢**中選擇一位人員，即可查看應用程式確切會取得哪些結果，或檢查單一權限。

平台本身的角色在**角色與存取權**中管理，而非在此處。

## 以 API 用戶端授予其他系統存取權

API 用戶端是供其他系統使用的服務帳戶：查詢角色查詢 API 的應用程式、呼叫平台 API 的指令碼，或外部 AI 代理程式。在示範資料中，**Finance ERP role sync** 可以查詢 Finance ERP。

1. 前往**系統管理 → API 用戶端**，選擇**建立用戶端**。
2. 輸入**名稱**與**描述**，然後選擇**可查詢的應用程式**（或**所有應用程式**）。
3. 若需要使用其他平台 API，請開啟**進階：平台權限、IP 範圍**，加入**平台 API 權限**（例如 `core.users.read`），並視需要加入**允許的 IP 範圍**。
4. 設定**第一個密鑰的到期時間**，然後選擇**建立用戶端**。
5. 複製**用戶端密鑰（API 金鑰）**，勾選**我已將密鑰妥善保存**，然後選擇**完成**。

**後續流程：** 該系統會將金鑰作為持有人權杖（bearer token）傳送，或以用戶端 ID 與密鑰交換有效期一小時的 OAuth 權杖。若要在不中斷服務的情況下輪替，請開啟用戶端並選擇**新增密鑰**，部署新的密鑰後，再**撤銷**舊的密鑰。**撤銷用戶端**會完全停用該用戶端。API 用戶端絕不能使用「我的申請」等個人功能。端點說明請參閱 [API 指南](../../api.md)。

## 連接登入提供者

讓人員使用我們的身分識別提供者或目錄登入。本機帳號仍可同時使用。

1. 前往**系統管理 → 登入提供者**，選擇**新增提供者**。
2. 選擇 **Microsoft Entra ID**、**通用 OpenID Connect**、**SAML 2.0** 或 **LDAP / Active Directory**，並填寫表單（Entra ID 需要租用戶 ID、應用程式（用戶端）ID 與用戶端密碼）。
3. 在**佈建**下，決定是否要**首次登入時建立人員**、**預設部門**，以及**群組對應**（提供者中的群組 → 平台群組）。若是 LDAP，請開啟**依排程同步**，以根據目錄建立、更新與停權人員。
4. 選擇**新增提供者**。在身分識別提供者中註冊畫面上顯示的值（例如**重新導向 URI** 或**判斷提示取用者服務（ACS）URL**）。
5. 選擇**測試連線**，然後使用提供者卡片上的開關將其開啟。

**後續流程：** 提供者會出現在登入頁面上。新提供者預設為停用，因此在您開啟之前，沒有人會看到它們。在示範資料中，**Microsoft Entra ID** 與 **Corporate Active Directory** 是保持停用的範例。

## 設計簽核流程

簽核流程決定由誰簽核權限申請、表單申請，以及各模組的工作，例如變更（**變更授權**）、資產報廢、專案提案、資料庫存取、發佈與變更集審核。

1. 前往**系統管理 → 工作流程**。工作流程會依其用途（**用於**）分組；**一律執行**標示的是永遠無法關閉的簽核。
2. 選擇**新增工作流程**（或觸發條件旁的**新增**），在**用於**中選擇用途、輸入**名稱**，並決定是否要從複本開始（**起點**），然後選擇**建立並開啟**。
3. 在畫布上選擇**在此新增步驟**，然後選擇步驟：
   - **簽核**：請人員核准或駁回。
   - **判斷**：依申請內容走不同路徑（例如表單上的金額）。
   - **平行處理**：同時進行多個簽核。
   - **通知**：通知相關人員，不需要做決定。
4. 選取步驟，並在**步驟**分頁上設定：
   - **簽核者**：**指定人員**、**群組**、**角色持有者**、**主管**、**部門主管**、**欄位中的人員**或**申請人**，每一種都可以設定備援對象（**若找不到人，改請**）。
   - **需要多少人核准**：**第一個回覆即決定**、**所有簽核者**或**指定人數**。
   - **僅在特定情況執行此步驟**：條件，例如金額超過上限。
   - **期限**：**須在此時間內處理**、**提醒時間**，以及**超過期限時**（通知、轉呈、自動核准或自動駁回）。
   - **選項**：轉交、自行核准（預設為關閉），以及**找不到簽核者時**。
   - **給簽核者的說明**。
5. 在**工作流程**分頁上，於**使用表單欄位**中選擇一份表單，讓條件可以判斷其答案。
6. 選擇**儲存草稿**。

在示範資料中，**Laptop request approval** 會先請部門主管簽核；當預估金額超過新台幣 60,000 元時，再請具有**資產管理員**（Asset manager）角色的人員簽核。

## 測試並發佈工作流程

在人員開始仰賴工作流程之前先測試，然後再發佈。

1. 在編輯器中開啟**測試**分頁。輸入範例的**申請內容**與**決定**，然後選擇**執行測試**。畫布會顯示哪些步驟會執行、被略過或等待中。不會儲存或寄送任何內容。
2. 選擇**發佈**。系統會顯示「已發佈第 … 版，新的申請會立即使用」以確認。
3. 若要讓它成為其觸發條件所使用的流程，請開啟**更多動作**並選擇**用於新的申請**。若是表單，請改在表單的**設定**分頁上附加流程：每份表單都會自行選擇工作流程。

**後續流程：** 進行中的申請會沿用它們開始時的版本。您可以在**進行中與歷史紀錄**分頁上追蹤所有進行中的簽核。**停止使用（不需簽核）** 會關閉選用觸發條件的簽核，**封存**則會讓工作流程停用。

## 建立申請表單

申請表單是人員在入口網站中填寫的表單：設備、軟體，以及任何 IT 提供的項目。

1. 前往**系統管理 → 表單**，選擇**新增表單**。輸入**名稱**、**代碼**、**圖示**與**類別**，然後選擇**建立並開啟編輯器**。
2. 在**編輯**中，將欄位從**新增元素**拖曳到表單上，或按一下欄位即可加入。選取欄位以設定其**標籤**（English、繁體中文與日本語）、**代碼**、**說明文字**、**必填**、選項，以及條件式欄位的**僅在以下情況顯示此欄位…**。
3. 在**預覽**中，以每種語言試填表單並送出，檢查答案。
4. 在**設定**中，於**適用對象**下選擇誰可以看到表單（**所有人**或**特定群組**）、是否**接受申請**，以及其**簽核**流程。
5. 選擇**儲存**，然後選擇**發布**。

**後續流程：** 表單會出現在入口網站中。透過表單提出的申請會列在其**申請**分頁上。再次發布會建立新版本；已送出的申請會保留原本的版本。若要讓服務台處理已核准的申請，請將表單加入服務目錄（請參閱[服務台指南](service-desk.md)）。

## 新增自訂欄位

為人員、群組、部門與模組紀錄（工單、硬體資產、合約、組態項目、專案、工作項目與應用程式）加入組織需要的欄位，例如成本中心或辦公室。

1. 前往**系統管理 → 自訂欄位**，選擇紀錄類型。
2. 選擇**新增欄位**。選擇**欄位類型**，輸入**標籤**與**代碼**，並如同表單一樣設定**必填**、選項與條件。
3. 選擇**新增**。

**後續流程：** 欄位會出現在紀錄表單與頁面的**其他資訊**區段，以及篩選條件中。欄位建立後，代碼與類型就無法變更。**封存**會隱藏欄位，但保留其值。

## 設定通知通道與電子郵件

人員會在應用程式中收到通知，若他們願意，也可以透過電子郵件收到。通道還會將選定的通知發布到團隊頻道或其他系統，例如將呈報轉送到 IT 值班頻道。

1. 前往**系統管理 → 通知**。
2. 在**電子郵件**中，開啟**寄送通知郵件**，輸入 **SMTP 伺服器**、**連接埠**、**加密方式**、登入資訊與**寄件者**，然後選擇**儲存變更**。選擇**寄送測試郵件**即可檢查設定。
3. 在**通道**中選擇**新增通道**。選擇**類型**（**Microsoft Teams**、**Slack** 或 **Webhook**）、**名稱**、**Webhook 網址**（表單會說明取得方式）、**訊息語言**，並在**通知**下選擇要接收的類型（整個模組或單一類型）。選擇**新增通道**。
4. 在通道上選擇**傳送測試**，即可發布一則測試訊息。

**後續流程：** Webhook 網址會加密儲存，且不會再次顯示。一般 Webhook 會取得一個簽章密鑰（只顯示一次），讓接收端系統可以驗證每個要求。**傳送紀錄**會顯示每封電子郵件與每則通道訊息及其狀態；傳送失敗時會重試數次。Webhook 網址必須是公開的 `https://` 位址。在示範資料中，**IT Operations (Microsoft Teams)** 與 **#it-approvals (Slack)** 是已關閉的範例通道。

## 管理模組及其設定

每項功能都是一個模組，模組可以在執行期間關閉，而不會遺失資料。

1. 前往**系統管理 → 模組**。每張卡片都會顯示模組是否已開啟。
2. 使用卡片上的開關開啟或關閉模組。其他模組所依賴的模組必須保持開啟，直到那些模組關閉為止；ISBP 會告訴您是哪些模組。
3. 開啟模組，即可查看其權限、事件、AI 工具，以及其背景 AI 工作所使用的身分。在**設定**中變更其設定，然後選擇**儲存變更**。

例如，服務台 AI 的設定可以為分派開啟**自動套用高信心度的建議**，核心平台的設定則包括附件大小上限與封鎖的檔案類型。

## 設定 AI

AI 功能不需要模型也能運作（內建模式）。新增模型即可啟用生成式回答，以及向助理提出自由文字需求。人員會看到哪些變化，請參閱[助理與 AI](assistant-and-ai.md)。

1. 前往**系統管理 → AI**。頁面頂端會顯示模式、嵌入向量模型、向量儲存區與本月花費。
2. 在**模型**的**對話模型**下，選擇**供應商**：**無**、**Anthropic（Claude）** 或 **OpenAI 相容**（OpenAI、Azure OpenAI、Ollama、vLLM 等）。輸入 API 金鑰與模型；若需要成本估算，也請輸入價格。選擇**儲存變更**，然後選擇**測試連線**。
3. 在**嵌入向量**下，保留**內建**（離線、不需金鑰），或選擇 OpenAI 相容模型。變更後，系統會在背景重新嵌入索引。
4. 在**隱私與預算**中，保持開啟**資料離開平台前先行遮罩**，選擇**要遮罩的資料**，視需要加入**自訂規則**，並設定每月**預算**（0 表示不限）。選擇**儲存變更**。
5. 在**使用量**中，依功能與模型查看呼叫次數、Token、成本與已遮罩的值。在**索引**中，查看語意搜尋可以引用的內容，並在變更模型後選擇**立即重新嵌入**。
6. 在**外部代理程式（MCP）** 中，查看 MCP 端點、可使用它的 API 用戶端，以及連接 Claude Code 的命令（請參閱[連接外部代理程式](assistant-and-ai.md#透過-mcp-連接外部代理程式)）。

金鑰會加密儲存，且不會再次顯示。

## 查看稽核日誌

稽核日誌會記錄每項變更、登入與存取決策。它無法編輯，而且每筆紀錄都會以雜湊值與前一筆串連，因此任何竄改都會留下痕跡。

1. 前往**系統管理 → 稽核日誌**。
2. 依執行者、目標或動作搜尋，並依**類別**（**資料**、**安全性**、**系統**）、**結果**、**模組**與日期篩選。
3. 開啟一筆紀錄，即可查看變更的欄位、詳細資料與情境。選擇**驗證雜湊**，即可在伺服器上檢查該紀錄是否完整。
4. 選擇**匯出 CSV**，即可下載此頁的資料列。

由變更集套用的變更會註明該變更集；由同步所做的變更會註明連線與遠端紀錄；為整合開啟**允許不安全的 HTTP** 屬於**安全性**事件。

## 管理助理

只有您授予的人員才能使用助理。

- **助理使用者**（Assistant user）可以使用助理，並為自己能讀取的設定準備變更集。
- **助理管理員**可以看到所有變更集，並可編輯、捨棄或撤回任何人的變更集。
- **組態檢視者**（Configuration viewer，系統角色）可以讀取工作流程、表單、自訂欄位、角色與模組設定，因此能對這些項目提出變更，再由其他人套用。

在示範資料中，IT 群組是助理使用者，IT 管理員是助理管理員，服務台則具有**組態檢視者**角色，因此服務台會準備變更並要求審核。

**審核**：送交審核的變更集會執行**變更集審核**工作流程。預設由一位平台管理員核准。若要改用不同的簽核路徑（例如將角色變更交給身分識別管理員），請在**系統管理 → 工作流程**中為**變更集審核**建立工作流程，加入依變更集內容（設定類型、模組、變更數量，以及是否會封存或刪除項目）判斷的**判斷**步驟，發佈後選擇**用於新的申請**。核准即會以簽核者的權限套用變更集。

**變更集**：**系統管理 → 變更集**會顯示您自己的變更集；**全部**分頁則供助理管理員查看所有人的變更集，包括外部代理程式準備的變更集。助理模組設定中的**每次回答的工具呼叫回合數**，可限制助理每次回答所做的工作量。

## 常見的管理工作

大多數設定都可以在管理頁面上變更，或由助理準備成變更集（自由文字需要對話模型；引導式範本則不需要）。有些工作只能在管理頁面上進行。

| ---------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 為超過新台幣 60,000 元的筆電新增簽核步驟 | **工作流程** → 筆電申請的工作流程 → **在此新增步驟** → 設有金額條件的**簽核** → **發佈**  | 「超過 60,000 元新台幣的筆電申請，也需要 IT 資產管理的簽核」，或使用**簽核鏈**範本                     |
| 為資產新增成本中心欄位                   | **自訂欄位** → **硬體資產** → **新增欄位**                                                | 「為硬體資產新增成本中心欄位」，或使用**自訂欄位**範本                                                 |
| 將重大事件傳送到 Teams 頻道              | **通知** → **通道** → **新增通道**（**Microsoft Teams**），並選擇**重大事件（通知管道）** | 僅限既有通道：「也將重大事件傳送到 IT Operations (Microsoft Teams)」。新通道及其網址需在管理頁面上新增 |
| 建立第二台螢幕的申請表單                 | **表單** → **新增表單** → **發布**                                                        | 「建立第二台螢幕的申請表單」，或使用**申請表單**範本                                                   |

| 給予約聘人員 30 天的模組存取權           | **角色與存取權** → **授予角色** → **30 天**                                               | 只能在管理頁面上進行（或由當事人在入口網站中申請）                                                     |
| 為人員辦理離職停用                       | **人員** → 該人員 → **更多動作** → **離職停用**                                           | 使用對話模型時說「為 … 辦理離職停用」；執行前，您需在卡片上確認                                        |
