## 共用的基礎元件

ISBP 的每個區域都由相同的元件組成，因此只要在一個地方熟悉了它們，到哪裡都適用。

| 基礎元件   | 對您的意義                                                                                                                                                                                                             |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 申請與簽核 | 凡是需要決定的事項（存取權、採購、變更、報廢、專案提案、資料庫角色、變更集），都會經過**簽核流程**。簽核者在同一個收件匣**簽核**中做決定；申請人可以查看**簽核路徑**。管理員在**系統管理 → 工作流程**中設計簽核流程。  |
| 通知       | 頁首的鈴鐺，以及電子郵件、Microsoft Teams、Slack 或 Webhook。您可以依類型選擇要在應用程式內或透過電子郵件收到哪些通知（**個人資料與偏好設定 → 通知**）。通知內容會以您的語言撰寫。                                     |
| 紀錄與連結 | 工單、變更、資產、組態項目、發行版本、工作項目與其他紀錄，都可以在**連結的紀錄**面板中（**連結紀錄**）跨區域互相連結。您只會看到自己有權開啟的連結紀錄。                                                               |
| 附件       | 螢幕截圖、合約與文件都放在紀錄的**附件**面板中。檔案在儲存前會先經過檢查。                                                                                                                                             |
| 自訂欄位   | 管理員可以在**系統管理 → 自訂欄位**中，為人員、群組、部門與模組紀錄新增我們自己的欄位（例如成本中心、受影響的據點）。表單也使用同一種欄位。                                                                            |
| 角色與權限 | 您能看到與能做的事都來自角色。角色可以指派給您或您的群組，有時只限於某個部門或某一筆紀錄，有時設有到期日。**個人資料與偏好設定 → 我的存取權**會列出您的角色。                                                          |
| 稽核日誌   | 每一次變更、登入與存取決定都會記錄在**系統管理 → 稽核日誌**中，且無法編輯。                                                                                                                                            |
| AI 與助理  | **詢問 IT** 依據知識庫回答員工的問題。**服務台 AI** 協助處理人員分派與回覆工單。頁首的**助理**可以在任何頁面與您一起工作，並將設定變更準備成變更集。這些功能都以您的權限運作，並會在任何資料離開平台之前遮罩個人資料。 |

## 情境：新進人員週一報到

一位業務部的新同事下週到職。HR 建立帳號，主管訂購筆電並申請存取權，新同事在第一天就能登入。

參與人員：HR 夥伴（在示範資料中為 `hr.partner`，負責管理 Sales 部門的人員）、新進人員的主管、簽核者、服務台與資產管理員。

1. HR 夥伴開啟**系統管理 → 人員**，選擇**新增人員**，填寫個人資料（部門、主管），並在**初始狀態**下選擇**預先建立**：帳號已經存在，但還無法登入。請參閱[管理員](administrators.md)。
2. 主管訂購筆電：在**申請 → 申請筆電或設備**中勾選**為他人申請**，在**使用者是誰？** 中選擇新同事，然後選擇**送出**。表單的簽核會在**簽核**中進行，核准後的申請會成為服務台工單。請參閱[申請設備或軟體](employees.md#使用表單申請設備或軟體)。
3. 主管在到職日前申請存取權：在**申請 → 申請權限**中選擇角色（例如 **Finance ERP** 的角色），在**誰需要此權限？** → **其他人**中選擇新進人員（標示為**預先建立**），設定期間與原因，然後選擇**送出申請**。確認步驟會顯示由誰簽核。請參閱[申請權限](employees.md#申請應用程式或角色的權限)。
4. 簽核者在**簽核**中做決定。請參閱[核准或駁回申請](employees.md#核准或駁回申請)。最後一位簽核者核准後，系統會自動授予角色並設定到期日。角色會在該人員到職啟用後生效。
5. 到職第一天，HR 夥伴在該人員的頁面上選擇**到職啟用**。新進人員現在可以登入，存取權也立即可用：他們可以在**個人資料與偏好設定 → 我的存取權**中看到，而透過角色查詢 API 向 ISBP 查詢誰擁有哪些角色的業務應用程式，也會看到這項授權。
6. 資產管理員在**資產 → 硬體**中找到一台**庫存中**的筆電，選擇**配發**並選擇新進人員。筆電會變為**使用中**，並出現在新進人員的**我的設備**中。接著處理人員在工單上選擇**完成**。請參閱[資產](assets.md)。**知識庫**中的 **New joiner IT checklist** 文章涵蓋了新同事第一週的其他事項。

> **注意：** 您可以為在職及預先建立的人員申請存取權。為已停權或已離職停用的人員提出的申請會遭拒絕。若該人員在申請等待簽核期間遭停權或離職停用，申請會以**無法授予**結束，且不會授予任何權限。

> **提示：** 有人離職時，在其頁面上選擇**離職停用**會停用其登入、結束其工作階段、可移除其群組與角色，並通知其他區域，例如移除其資料庫帳號。

## 情境：「我的 VPN 一直斷線」

一位在家工作的員工每隔幾分鐘就斷一次 VPN。大多數情況下，一篇知識文章就能解決；否則就由服務台處理，而這次的解法也會讓下一次的回答更好。

參與人員：員工、詢問 IT、服務台專員（在示範資料中為 `helpdesk`）、網路團隊。

1. 員工開啟**詢問 IT** 並輸入「VPN 一直斷線」。詢問 IT 會依據知識庫回答（在示範資料中依據 **VPN disconnects every few minutes**），並將該文章列在**參考來源**下。
2. 如果步驟有效，員工選擇**已解決**：不需要工單。否則依序選擇**仍需要協助**、**檢視工單**與**建立工單**。請參閱[詢問 IT](employees.md#建立工單前先詢問-it)。
3. 事件會出現在**服務台 → 工單**中。服務台 AI 會建議類別（VPN）、指派群組與優先順序，並顯示相似的已解決工單。SLA 開始計時。
4. 處理人員發現這張工單符合已知錯誤 **VPN client 5.2 crashes on macOS 15**（**服務台 → 問題**中的一個問題），於是套用其暫時解法並解決工單。請參閱[服務台](service-desk.md)。
5. 員工收到通知後開啟工單，選擇**是，可以結案**並為服務評分。請參閱[確認問題已解決](employees.md#確認問題已解決並為服務評分)。
6. 如果知識庫中還沒有這個解法，處理人員可以將工單轉成文章草稿，由編輯者審閱並發佈，讓詢問 IT 能回答下一個人。

## 情境：超過新台幣 60,000 元的筆電

筆電申請由部門主管簽核；超過新台幣 60,000 元時，還需經 IT 資產管理簽核。核准後的申請由服務台完成，最後成為配發給申請人的資產。

參與人員：員工、其部門主管、資產管理員、服務台專員。

1. 員工開啟**申請**，選擇**筆電申請**，選擇**機型**，輸入**預估金額（新台幣）**（例如 72,000）與**申請原因**，然後選擇**送出**。請參閱[申請設備或軟體](employees.md#使用表單申請設備或軟體)。
2. 首先是**部門主管簽核**。由於金額超過新台幣 60,000 元，接著是由資產管理員決定的 **IT 資產管理**步驟。兩者都在**簽核**中做決定。
3. 核准後，申請會成為**硬體 › 筆電**類別中的服務請求工單，交由服務台處理。申請人的申請頁面會顯示**處理中**與**開啟 SR-…**。
4. 資產管理員在**資產 → 硬體**中從庫存配發一台筆電（**配發**），並在工單的**連結的紀錄**下將該資產連結到工單。
5. 處理人員在工單上選擇**完成**。申請頁面會顯示**已完成**，筆電也會出現在員工的**我的設備**中。

> **提示：** 在示範資料中，這整套設定（簽核流程、表單與服務目錄項目）是透過助理以變更集 `CS-00001` 建立的。請參閱[使用助理變更流程](#情境使用助理變更流程)。

## 情境：正式環境發行

Finance ERP 團隊正在升級到 12.1 版。工作在專案中規劃，版本以發行版本追蹤，正式環境需要一項經 CAB 核准的變更，部署則由管線記錄。

參與人員：專案經理與專案團隊、應用程式負責人或發行經理、變更經理與 CAB、CI/CD 管線。

1. 在**專案 → 專案**中，**ERP upgrade to v12** 專案有一個工作項目 **Change request for the production cutover**。請參閱[專案](projects.md)。
2. 在**應用程式 → 應用程式**中，發行經理開啟 **Finance ERP**，接著開啟**發行版本**，再開啟 **12.1.0 (ERP v12 upgrade)**。**正式環境就緒檢查**會列出各項檢查：**已連結核准的變更**、**已在測試或預備環境成功部署**、**已撰寫發行說明**、**沒有失敗的正式環境部署**。
3. 發行版本需要一項變更。在示範資料中已經有一項，即草稿 **Deploy Finance ERP 12.1.0 to production**；否則由變更經理在發行版本上選擇**提出變更**（沒有**變更經理**（Change manager）角色的發行經理看不到此按鈕），新的變更會在**服務台 → 變更**中開啟，標題已預先填入，並已連結到該發行版本。他們完成變更計畫（變更類型**一般**、風險、預計時段、實施計畫、回復計畫與測試計畫），然後選擇**送出簽核**。請參閱[變更與發行](changes-and-releases.md)。
4. **變更授權**簽核流程會先詢問**變更經理**，若風險高或涉及關鍵組態項目，再詢問**變更諮詢委員會 (CAB)**。變更會顯示**等待 CAB 簽核**，接著變為**已排程**。
5. 專案經理在專案工作項目的**連結的紀錄**下連結此變更，讓專案顯示正式環境切換的進度。
6. 在變更時段內，管線進行部署，並透過 API 在 ISBP 中記錄部署（使用具有 **CI/CD 管線**（CI/CD pipeline）角色的 API 用戶端）。ISBP 會檢查變更政策：正式環境的部署需要一項經 CAB 核准、且在其時段內的變更。若沒有，部署會遭拒絕，除非有權略過政策的人提供原因，而此動作會被稽核。
7. 發行經理將發行版本移至**已發行**。應用程式上的**交付指標**（部署頻率、變更前置時間、變更失敗率、服務復原時間）會納入這次部署。

## 情境：ERP 資料介接

財務部門希望每四小時將銷售數據匯入資料倉儲，報表團隊則希望以 API 取得 ERP 資料。資料介接失敗時，其負責人會收到通知。

參與人員：資料庫連線管理員、資料工程師、作業擁有者與擁有群組（在示範資料中為 DBA 團隊）。

1. 資料庫連線管理員在**系統管理 → 資料庫連線**中登錄 ERP 資料庫（在示範資料中為 **Contoso ERP (reporting)** 與 **Contoso data warehouse**），認證資訊會加密儲存，用途設為**資料**。請參閱[資料與自動化](data-and-automation.md)。
2. 資料工程師在**資料 API 與 ETL → 資料 API** 中，以含參數的 SQL 發佈資料 API（在示範資料中為 **Customers by region**）、進行測試，並允許可以呼叫它的 API 用戶端。
3. 他們在**資料 API 與 ETL → 管線**中建立管線，將資料列從 ERP 複製到資料倉儲（在示範資料中為 **Daily sales to warehouse**）。
4. 排程作業在**排程作業 → 作業**中執行此管線（在示範資料中為 **Sales to warehouse (every 4 hours)**），並設定重試，且開啟**執行失敗時通知擁有者及擁有群組**。
5. 某次執行在最後一次重試後仍失敗時，負責人會收到通知（**我的作業執行失敗**），並在**排程作業 → 執行紀錄**中開啟該次執行的記錄檔。在示範資料中，**CRM accounts to warehouse** 會因為無法連線到其 MySQL 伺服器而失敗。作業連續失敗多次後會被停用，直到有人修正問題並重新啟用為止。

## 情境：開發人員的資料庫存取

一位開發人員需要讀取 ERP 報表資料庫兩週，以調查一個錯誤。他不需要任何人分享密碼就能取得帳號，而存取權到期後會自動結束。

參與人員：開發人員、其主管、角色擁有者、資訊安全團隊（針對高風險角色）、DBA、審查者。

1. 開發人員開啟**申請 → 申請資料庫存取**，選擇角色（在示範資料中為 **Contoso ERP (PostgreSQL)** 上的 **ERP 報表（唯讀）**）、結束日期與原因，然後送出。請參閱[申請資料庫存取](employees.md#申請資料庫存取)。
2. **主管簽核**、**角色擁有者簽核**，以及針對高風險角色的**資訊安全簽核**，都在**簽核**中決定。
3. ISBP 會自動建立帳號，並在資料庫伺服器上授予角色。
4. 開發人員收到**您的存取已就緒**通知，開啟**資料庫存取 → 我的資料庫存取**並選擇**顯示密碼**，密碼只會顯示一次。
5. 結束日期前幾天，開發人員會收到提醒（**您的 … 存取即將到期**），並可以申請延長。到了結束日期，角色會自動移除。
6. 審查者會定期檢視**資料庫存取 → 存取審查**，針對每項存取選擇**保留**或**撤銷**。DBA 也能看到在 ISBP 以外授予的存取（**未受管理的存取**），並可將其納入管理。請參閱[資料與自動化](data-and-automation.md)。

## 情境：與 ServiceDesk Plus 及 Azure DevOps Server 並行作業

有些團隊仍在 ManageEngine ServiceDesk Plus 與 Azure DevOps Server（兩者皆為地端部署）中工作。ISBP 會雙向同步紀錄，同時仍套用自己的規則（簽核、變更政策）。

參與人員：整合管理員、服務台專員、專案團隊。

1. 整合管理員在**系統管理 → 整合**中連接各個系統（在示範資料中為 **Contoso ServiceDesk Plus** 與 **Contoso Azure DevOps Server**）。請參閱[整合](integrations.md)。
2. 同步設定檔說明要同步什麼、往哪個方向，以及欄位如何對應。在示範資料中，與 ServiceDesk Plus 之間有 **Requests ↔ tickets**、**Problems → tickets**、**Changes → changes**、**Assets ↔ assets** 與 **Solutions → knowledge**；與 Azure DevOps Server 之間有 **Team projects → projects**、**ERP work items ↔ tasks** 與 **Network work items → tasks**。
3. 在已同步的紀錄上，**同步對象**卡片會顯示遠端紀錄及上次同步的時間；**立即同步**可以重新整理。
4. 當雙方都變更了同一欄位時，設定檔可以要求由人員決定。衝突會在**系統管理 → 整合 → 同步衝突**中等待處理，由管理員選擇**保留 ISBP 的值**、**保留 … 的值**或**保持雙方現狀**。
5. 在另一個系統中所做的變更仍須遵守 ISBP 的規則。在示範資料中，在 ServiceDesk Plus 中報廢的資產會等待 ISBP 的報廢簽核。

## 情境：使用助理變更流程

服務台希望在每張工單上記錄受影響的據點。組長向助理描述需求，由管理員審核；若結果有誤，也可以一步回復。

參與人員：服務台組長（在示範資料中為 `helpdesk`）、負責審核與套用的管理員。

1. 組長開啟頁首中的**助理**，要求在工單上新增一個選項欄位「受影響據點」，選項為台北總部、新竹與東京。若沒有 AI 對話模型，**自訂欄位**引導式範本會詢問相同的問題。
2. 助理會準備一個變更集：列出將要變更的內容、易讀的差異比較，以及**試行**（在不儲存的情況下嘗試整組變更）。此時尚未有任何內容生效。
3. 組長沒有權限變更自訂欄位（他們具有**組態檢視者**（Configuration viewer）角色，只能提出建議），因此選擇**要求審核**。在示範資料中，這就是 `CS-00002`，正在管理員的**簽核**中等待。
4. 管理員在**簽核**中審核變更集（**變更集審核**）並核准。核准即會以核准者的權限，在單一交易中套用變更集。
5. 若有誤，具備權限的人可以開啟**系統管理 → 變更集**，開啟該變更集並選擇**回復**。若之後有人變更了相同的設定，ISBP 會拒絕回復，並要求對方先重新整理並檢閱差異。

請參閱[助理與 AI](assistant-and-ai.md)。
